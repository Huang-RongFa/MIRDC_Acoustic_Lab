# 2026-11-16 更新 v4：支援 EARS（左右同一時鐘）＋ UMIK-2

分支：`claude/analysis-model-sync-v1`（延續 v3，新增一個 commit）。
狀態：**已測試、已推送分支、尚未合併**。

## 一、為什麼做

現有設備是 miniDSP EARS（雙聲道，左右各一支麥克風）和 UMIK-2（單聲道）。

- EARS 的左右兩軌在同一台 USB 裝置上，共用一個時鐘：沒有起點差，也沒有漂移。量到的相位差就是聲學到達時間差，比三支手機更適合做相位。
- UMIK-2 有自己的時鐘，和手機一樣需要對齊。

v3 的工具還不能用在這組設備上，有三個原因：

1. `offline.py` 解碼時把立體聲混成單聲道，EARS 左右的相位差會消失。
2. 模型會把 B 軌重新對齊到 A 軌。這對手機是必要的，但用在 EARS 左右軌，會把真正的到達時間差抹掉。
3. Windows 內建錄音程式一次只能錄一個裝置。

### 模型：同一時鐘的配對

- **不對齊**：只量 A–B 的聲學到達時間差（B 比 A 晚到為正），記錄下來，不補償。相位用原始兩軌計算。
- **間距檢查**（有給間距時）：
  - 算出直線上限 d/c 和相位不混疊的頻率上限 c/(2d)；
  - 時間差超過直線上限：提醒；
  - 超過 1.5 倍再加 1 取樣點：判定不通過，代表間距填錯，或兩軌其實不是同一個時鐘。
  - 1.5 倍是留給治具繞射的餘裕：EARS 的兩支麥克風之間隔著治具本體，聲音繞過去的路徑比直線長。這個倍數是我取的保守值，沒有用 EARS 實測過。
- **趨勢提醒**：到達時間差隨時間變化超過 5 ppm 時提醒（聲源在移動，或不是同一個時鐘）。只提醒、不判定失敗，因為刀具移動本來就會讓到達時間差改變。
- **背景移除**：「各軌平均」先把 B 朝主聲源對正再平均，否則高頻會互相抵消。只影響背景移除這一步；相位與輸出的 `B_aligned.wav` 都是原始的 B。
- **手機路徑不變**：沒有宣告同一時鐘時，`summary.json` 與修改前逐項相同（見第三節）。

### 對齊判定

- 同一時鐘的配對硬體上本來就同步，不檢查「對齊後殘差」。只有在給了間距、且時間差超過物理上限時，才判定不通過。
- 網站錄音的路徑不會出現同一時鐘的配對，判定結果的欄位與之前完全相同。

### 離線工具：`--stereo-ab`

- 把雙聲道檔拆成左（A）、右（B）兩軌，不混音。
- 會拒絕兩種檔案：
  - 不是雙聲道；
  - 左右兩軌完全相同（Windows 把單聲道複製成雙聲道時會這樣）。
- 第三支獨立麥克風用 `--c`，照舊對齊到 A。

### 錄音程式：`record_usb.py`

- `list`：列出音訊輸入裝置。
- `record --stereo EARS --mono UMIK --seconds 60 --out <資料夾>`：
  - 用內附的 ffmpeg（DirectShow）在同一個程序裡同時開兩個輸入，各存一個 48 kHz wav；
  - 先試 24 位元，裝置不支援時自動改用 16 位元；
  - 錄完檢查：聲道數、取樣率、長度、破音、幾乎沒聲音、左右是否相同；
  - 寫出 `recording.json`（裝置名稱、開始時間、各軌峰值與位準）；
  - 有問題時以代碼 1 結束，檔案仍會留下；
  - 拒絕把錄音寫進 Git 儲存庫。
- 不需要安裝新套件。只支援 Windows。

## 四、沒有驗證的

- **沒有接上 EARS 和 UMIK-2 實測。** 這台電腦只有內建麥克風，所以：
  - 兩台裝置同時錄音，只用測試確認指令的組成，沒有實際錄過；
  - EARS 和 UMIK-2 在 Windows 裡顯示的名稱、能不能用 24 位元開啟，都還不知道。
- **EARS 左右麥克風本身的相位差沒有校正。** 校正檔若只有頻率和 dB 兩欄，就沒有相位資料，需要自己量（見第五節第 2 步）。
- **Windows 可能對輸入做處理。** DirectShow 走 Windows 的共用音訊路徑。請在「音效 → 錄製 → 內容」把兩台裝置設成 48000 Hz，並關閉「音訊增強」。
- **1.5 倍的繞射餘裕**是保守取值，沒有量過 EARS 實際的最大時間差。

## 五、第一次使用的步驟（建議）

1. **確認裝置**：接上 EARS 和 UMIK-2，執行 `record_usb.py list`，確認兩台都列得出來。
2. **量左右麥克風的相位差**（只需做一次）：把一個小喇叭放在兩耳正中間的對稱位置（到兩支麥克風等距），播 30 秒寬頻聲音並錄下來，用 `--stereo-ab` 分析。這時到達時間差應該接近 0；量到的數值就是兩支麥克風加治具本身的差異，之後要從實驗結果扣掉。
3. **量間距**：用尺量兩個麥克風開孔中心之間的距離，填進 `--ab-spacing-m`。
4. **實錄**：照 `analysis/README.md` 的指令錄音並分析。UMIK-2 與 EARS 之間仍需要聲音對齊，錄音開頭要有明顯的聲音變化（例如開機），或播同步嗶聲。

## 六、下一步

## 七、EARS 實機第一次測試（2026-11-16，只接 EARS）

接上 EARS 後實際錄了 10 秒室內環境音。UMIK-2 還沒接。

### 找到並修正的問題

| 問題 | 原因 | 修正 |
|---|---|---|
| 錄音開不起來（`Malformed dshow input string`） | EARS 在 Windows 的名稱是「麥克風 (E.A.R.S Gain: 24dB)」。名稱裡的冒號被 ffmpeg 當成分隔符號 | 一律改用 Windows 裝置識別碼開啟（ffmpeg 列在名稱下一行），識別碼沒有冒號。已補回歸測試 |
| 量不到到達時間差時，報告印出「None 取樣點」，判定還寫「殘餘偏移 ≤ 2 取樣點」 | 報告沒有處理「量不到」的情況；只有同一時鐘的配對時，沒有對齊殘差可言 | 改成明講「量不到，請用明確的聲源再錄」；判定改寫「同一時鐘，硬體同步，不需要對齊」。已補測試 |

### 實測結果

| 項目 | 結果 |
|---|---|
| 裝置 | 「麥克風 (E.A.R.S Gain: 24dB)」，名稱顯示增益設定為 24 dB |
| 格式 | 2 聲道、48 kHz、**16 位元**。Windows 這條錄音路徑（DirectShow）最高只提供 16 位元，24 位元開不起來 |
| 左右是不同的訊號 | 是（不是單聲道複製） |
| 位準 | 左 −44.6 dBFS、右 −44.0 dBFS，相差 0.6 dB；沒有直流偏移 |
| 峰值 | 第 2.4 秒有一個較大的聲音，峰值 0.34（左）、0.37（右），沒有破音 |
| 左右相干度（中位數） | 20–100 Hz 0.99、100–300 Hz 0.85、300–1000 Hz 0.49、1–3 kHz 0.46、3–8 kHz 0.33、8–20 kHz 0.22 |
| 到達時間差 | 量不到：7 個分析窗中沒有一個峰值清楚 |

判讀：

- 兩支麥克風都正常，位準相近。
- 低頻相干度高、往高頻下降，符合「沒有單一主要聲源的室內環境音」：聲音從四面八方來，頻率越高，兩支麥克風收到的越不一樣。
- 量不到到達時間差是因為沒有明確的聲源，不是設備或程式的問題。合成資料的測試（單一聲源）量得到。

### 還需要確認的

- **增益可能太高。** 室內環境音在 24 dB 增益下已經有 −44 dBFS，離滿刻度只剩 44 dB。機台運轉聲比室內環境音大很多，很可能破音。建議錄機台前把 EARS 的增益開關調低，先試錄一段；錄音程式會回報破音。室內環境音的實際音量我沒有量，所以這是推估。
- **16 位元夠不夠**：機台聲音量大時夠用。若要 24 位元，需要改用別的錄音路徑（例如 WASAPI 或 ASIO），需要另外安裝套件，這次沒做。
- 還沒用明確的聲源測到達時間差，也還沒做左右麥克風的相位校正（第五節第 2 步）。

### 第二次測試：用電腦喇叭播測試音（未完成）

做法：電腦左喇叭播 15 秒 200–8000 Hz 噪音（前 3 秒靜音），同時錄 EARS 22 秒。

- **測試音沒有播出來。** 查到預設播放裝置「喇叭 (Realtek(R) Audio)」是靜音狀態（音量 56%、靜音開啟）。我只讀取了狀態，沒有更改。錄到的 22 秒裡沒有持續 15 秒的噪音平台，只有零星的環境聲。
- **錄音本身正常**：2 聲道、48 kHz、21.991 秒，沒有掉資料。

這段錄音另外看到兩件事：

| 觀察 | 數字 |
|---|---|
| Windows 對 EARS 的輸入音量 | 71%，相當於 **+5.7 dB 的數位增益**（範圍 −96 到 +30 dB），沒有靜音 |
| 安靜時的訊號大小 | 第 9.3–10.0 秒，取樣值只有 −2 到 +2（16 位元的最小刻度），其中 0 佔 73%；全段有 6.9% 的取樣點左右都是 0 |
| 安靜底噪會變動 | 同一段錄音裡，沒有明顯聲音事件時的 10 毫秒峰值，有時是 1–2 個刻度，有時是 10–20 個刻度 |

這有兩種可能，目前分不出來：

1. **室內真的很安靜，EARS 的滿刻度對應很大的音量。** 那麼 16 位元對小聲音不夠用（安靜時只剩 1 個刻度），而上面「增益可能太高」的推估就不成立：第一次測試的 −44 dBFS 是當時有較大的聲音。
2. **Windows 對這個輸入做了降噪處理**，把穩定的底噪往 0 壓。

分辨方法：播一段音量穩定的測試音。位準穩定就是第 1 種；開頭幾秒位準逐漸下降就是第 2 種。

建議：把 Windows 對 EARS 的輸入音量調到 0 dB（不加數位增益），並確認「音訊增強」已關閉。這兩項是系統設定，由使用者調整。

### 第三次測試：重播（仍未播出）

喇叭仍是靜音，沒有錄到測試音。播放前已讀到靜音狀態卻仍然播放，是操作上的失誤；之後改成先確認再播。

### 第四次測試：耳機戴在 EARS 上

做法：Logitech G733 耳機戴在 EARS 上，播放 26 秒測試音（100–12000 Hz 噪音）：只有左耳 5 秒、只有右耳 5 秒、左右相同 10 秒。同時錄 EARS 29 秒。

用播放的原始訊號比對錄音（匹配濾波），確認測試音有被錄到，錄音比播放晚 2.72 秒開始。

| 播放的內容 | 錄到的結果 |
|---|---|
| 只有左耳 5 秒 | 出現在錄音的**右軌**：−43.3 dBFS，5 秒內穩定（−42.4 到 −43.9）。左軌 −55.9 dBFS |
| 只有右耳 5 秒 | 出現在錄音的**左軌**：−39.0 dBFS，5 秒內從 −36.8 降到 −42.0。右軌 −60.5 dBFS |
| 左右相同 10 秒 | 第 1 秒 −42／−41 dBFS，第 2 秒 −70，第 3 秒 −86，之後是 **−95 到 −100 dBFS（數位無聲）**，直到播放結束 |

兩個發現：

**1. 錄音被 Windows 的音訊效果改動了。**

- 左右相同的穩定噪音，播了約 1 秒就被壓到完全無聲，而這時耳機還在播。
- 查登錄檔（只讀取）：EARS 這個輸入裝置登記了效果包 `VocaEffectPack`，而且「音訊增強」沒有關閉。`VocaEffectPack` 是 Windows 11 的「語音清晰度」，功能是降噪、回音消除、去殘響。
- 這也解釋了第二次測試看到的現象：安靜時訊號被壓到 0、底噪忽大忽小。所以前面列的兩種可能中，是第 2 種（Windows 降噪）。
- 因果關係還沒有直接驗證：要等關掉「音訊增強」後重測，確認左右相同的噪音能穩定錄滿 10 秒。
- **影響**：機台運轉聲就是穩定的噪音，正是這個效果要消掉的東西。在關掉之前，用這條路徑錄的任何機台錄音都不能用。前面四段 EARS 錄音都受影響，其中的位準與相干度數字只能當作「設備有訊號」的證據。

**2. 左右對調。** 播放的左耳出現在錄音的右軌。可能是耳機反戴在 EARS 上，也可能是 EARS 的聲道順序與預期相反，從錄音分不出來。需要看 EARS 上的 L／R 標示與耳機的左右是否對應。

### 新增的防護

`record_usb.py` 錄音前會讀取登錄檔，檢查 Windows 是否對要錄的裝置啟用音訊效果。有的話：

- 錄音前印出警告，說明要到哪裡關閉；
- 寫進 `recording.json` 的 `problems` 與 `windows_effects`；
- 程式以代碼 1 結束（檔案仍會留下）。

實機檢查結果：EARS 回報 `VocaEffectPack` 作用中；G733 的麥克風回報 `Logitech Blue VO!CE Effect`；內建麥克風陣列有 253 項效果設定。

### 需要使用者調整的系統設定

1. **關閉 EARS 的音訊增強**：設定 → 系統 → 音效 → 輸入 → E.A.R.S → 音訊增強 → 關閉。（使用者已關閉，見第五次測試。）
2. **EARS 輸入音量調到 0 dB**（目前 +5.7 dB，第五次測試時仍未調整）。
3. 之後接上 UMIK-2 時，同樣要關閉它的音訊增強。

### 第五次測試：關閉音訊增強後重測（同一段測試音、耳機戴在 EARS 上）

測試前的狀態（只讀取）：EARS 的「音訊增強已關閉」旗標為 1，錄音程式回報效果不再作用；預設播放裝置是 G733，沒有靜音。

**1. 原因確認：是 Windows 的音訊增強。**

| 播放的內容 | 增強開啟（第四次） | 增強關閉（第五次） |
|---|---|---|
| 左右相同 10 秒 | 約 1 秒後被壓到 −95 至 −100 dBFS | 整段穩定：左 −33.9 至 −34.3、右 −35.1 至 −35.4 dBFS |
| 只有左耳 5 秒 | 出現在右軌 | 出現在**左軌**，−34 dBFS，穩定 |
| 只有右耳 5 秒 | 出現在左軌，5 秒內下降 5 dB | 出現在**右軌**，−35 dBFS，穩定 |
| 左右同時為 0 的取樣點 | 6.9%（第二次測試） | 0.00% |

- 這次左右沒有對調。第四次的對調是音訊增強造成的，還是耳機當時反戴，無法從錄音判斷。
- 播放結束後的底噪約 −46 至 −51 dBFS（100–12000 Hz），比測試音低 13–16 dB。

**2. 左右兩軌的差異**（取「左右相同」那段的中間 9 秒）

| 項目 | 結果 |
|---|---|
| 時間差（GCC-PHAT，整段） | 右軌比左軌晚 **1.71 取樣點（35.7 µs）** |
| 時間差（離線工具，每 2 秒一窗） | 1.62 取樣點（33.8 µs），5–95% 範圍 1.55–1.63，6 個窗全部清楚 |
| 逐秒時間差 | 9 秒都是 1.71 取樣點，沒有變動 |
| 隨時間的趨勢 | −0.08 ppm（合成測試以外，第一次在實機上確認左右同一個時鐘、沒有漂移） |
| 相位斜率換算的時間差 | −28.4 µs（自算，200–6000 Hz）、−33.1 µs（離線工具）；正負號與時間差相反，見 README |
| 位準差 | 左比右大 1.03 dB（整體）；分頻帶看，右減左在 −2.7 到 +1.6 dB 之間 |
| 相干度（中位數） | 1 kHz 以上 0.997–1.000；100–300 Hz 0.83、300–1000 Hz 0.88 |

判讀：

- 錄音路徑現在是乾淨的，離線工具在實機資料上量得到穩定的左右時間差。
- 35.7 µs 是三樣東西加在一起：EARS 左右麥克風的差、耳機左右單體的差、耳罩在治具上位置的差（35.7 µs 相當於約 12 mm 的路徑差）。**這個數字不能直接當作 EARS 的麥克風校正值。**
- 把麥克風和耳機分開的方法：把耳機左右對調再戴上，重測一次。兩次結果相加除以 2 是麥克風的差，相減除以 2 是耳機的差。耳罩位置造成的差仍會留在裡面，所以每次戴上後的重現性也要看。
- 1 kHz 以下相干度較低，是因為這個頻段的測試音只比底噪高一點。

### 第六次測試：耳機左右對調後重測

狀態與第五次相同（音訊增強關閉、輸入音量 +5.7 dB）。對調有生效：播放的左聲道這次出現在錄音的右軌，右聲道出現在左軌。

| 項目 | 正戴（第五次） | 對調（第六次） |
|---|---|---|
| 右軌比左軌晚 | 1.712 取樣點（35.7 µs） | 1.491 取樣點（31.1 µs） |
| 逐秒時間差 | 9 秒都是 1.71 | 9 秒都是 1.49–1.50 |
| 位準（右減左，100–12000 Hz） | −1.07 dB | −2.18 dB |

兩次相加除以 2 是「固定在 EARS 這一側」的差，相減除以 2 是「跟著耳機走」的差：

| | EARS 側（右減左） | 耳機側（右耳罩減左耳罩） |
|---|---|---|
| 時間差 | **+33.4 µs（1.60 取樣點）** | +2.3 µs |
| 位準（整體） | −1.62 dB | +0.56 dB |
| 位準 100–300 Hz | +0.38 dB | +0.19 dB |
| 位準 300–1000 Hz | −0.43 dB | +0.05 dB |
| 位準 1–2 kHz | −0.42 dB | +0.30 dB |
| 位準 2–4 kHz | −3.60 dB | +0.85 dB |
| 位準 4–8 kHz | −1.69 dB | +0.21 dB |
| 位準 8–12 kHz | −1.07 dB | +2.65 dB |

判讀：

- **左右時間差幾乎都來自 EARS 這一側**：右軌固定比左軌晚約 33 µs（1.6 個取樣點），耳機只佔約 2 µs。
- 33 µs 換算成相位是 1 kHz 約 12°、5 kHz 約 60°。之後用 EARS 左右軌做相位分析或背景抵銷時，必須先扣掉這個固定差。
- 「EARS 這一側」包含麥克風、錄音電路的左右聲道、治具耳道的形狀，這個測試分不開它們。1.6 個取樣點這種量級，有可能是錄音電路左右聲道本身的固定延遲，但沒有驗證。
- **限制**：每個方向只戴了一次，沒有量「拿下來再戴上」的重現性。兩次相差 4.6 µs，可能有一部分是戴的位置不同。所以 33 µs 的不確定度目前估不出來，至少要再各戴一次才知道。
- 這是耳機貼著耳道量到的值。用外部聲源（自由場）時，固定的電路延遲仍然會在，但治具外形造成的差會隨聲源方向改變。

**還沒做的**

- 重現性：同一方向拿下來再戴上，各重測一次。
- 分析工具還不會自動扣掉這 33 µs；目前要自己從結果扣。
- 用外部聲源量「同一個聲源到兩支麥克風」的到達時間差（需要喇叭或手機播放）。
- 增益是否適合錄機台：安靜時底噪已到 −50 dBFS 左右，機台聲大很多，有破音的可能。要到機台旁試錄才知道；錄音程式會回報破音。
- UMIK-2。
