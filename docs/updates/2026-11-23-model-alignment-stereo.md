# 2026-11-23 更新：對齊判定用同一把尺、漂移擬合排除反射窗、worker 保留雙聲道

分支：`claude/model-alignment-stereo-v1`（從 `main` f089605）。
狀態：**本機測試通過；沒有在 Jetson 實機上跑過；正式站沒有驗證。**

## 一、起因

2026-11-23 用一台雙聲道裝置（miniDSP EARS）加一支獨立麥克風（UMIK-2）在房間裡錄了 57 秒，經網站錄音、地端 worker 分析，結果是「對齊未通過驗證：對齊後無法重新量測」。追下去是三個問題。

## 二、改了什麼

### 1. 清晰度分數不再隨搜尋範圍改變（`analyze_multi_mic.py`）

- 分數＝GCC-PHAT 峰值 ÷ 背景中位數。原本背景只取搜尋範圍內的延遲。
- 主峰附近有反射時，範圍越窄、背景越高、分數越低。同一份對齊後的資料：

  | 搜尋範圍 | 分數中位數 | 清楚的窗（≥ 20） |
  |---|---|---|
  | ±5 ms | 14.2 | 0／54 |
  | ±25 ms | 20.1 | 28／54 |
  | ±50 ms | 25.0 | 45／54 |

- 第一次量用 ±25 ms，對齊後複驗用 ±5 ms，同一個門檻 20 變成兩種嚴格度。
- 現在背景一律取 ±25 ms（`SCORE_REF_MS`）。**門檻 20 沒有改。第一次量的分數逐位元不變。**
- 相位步驟的殘餘時間差（1 秒窗、±3 ms）也用同一把尺，所以 `residual_tdoa_windows.n_phat_ge_20` 會變多。

### 2. 漂移的直線擬合排除鎖到反射的窗（`analyze_multi_mic.py`）

- 修完第 1 項之後才看到：少數窗的峰值落在反射上（離直達聲約 23 個取樣點），分數仍過門檻。
  原本用所有清楚的窗做最小平方，直線被拉歪約 3.5 個取樣點；照著對齊後，其餘的窗全部讀到 −3.4。
- 現在先用 Theil–Sen 找出直線，離它超過 `max(2 取樣點, 3 × 1.4826 × MAD)` 的窗不參加最後的最小平方。
  2 取樣點就是對齊判定原本的殘餘偏移標準。
- 沒有窗被排除時，結果和原本的最小平方完全相同。
- 新增兩個欄位：`windows_used_for_fit`、`windows_rejected_as_outliers`。
- `fit_residual_std_samples` 現在只算參加擬合的窗。

### 3. worker 保留雙聲道（`worker.py`，pipeline `multi_mic-v2`）

- 原本每台裝置都混成單聲道，EARS 的左右兩耳變成一軌。
- 現在整場只有一台雙聲道裝置、拆開後不超過 3 軌時：左＝A、右＝B（同一時鐘，不對齊）、另一台＝C。
  只有一台雙聲道裝置的錄音也能分析了（原本判定為不支援）。
- 模型軌道和網站位置的對照寫在 `result.summary.track_sources`；處理方式寫在 `result.summary.stereo`。
- 其他情況照舊。詳細規則見 [`docs/analysis-worker.md`](../analysis-worker.md)。
- 拆開之後獨立麥克風對不上左聲道時，退回每台裝置一軌再算一次，並寫明原因。
- 單聲道複製成雙聲道的檔當成單聲道。判斷方式是左右相減的能量比訊號低 40 dB 以上：
  Opus 編碼後左右不會完全相同（實測 −70 dB），兩支真的麥克風約在 0 到 +2 dB。

### 4. Jetson Orin Nano 相依檢查

見 [`docs/jetson-orin-nano.md`](../jetson-orin-nano.md)。只有靜態檢查與 PyPI 查詢。

## 四、還沒有驗證或沒有做的

- **記憶體沒有處理。** 開發機上量到每秒錄音約用 50 MB；照比例估計 3 分鐘約需 9 GB，超過 Jetson Orin Nano 8GB 的實體記憶體。這是估計，沒有在 Jetson 上量過。
- **沒有在 Jetson 上跑過**，也沒有在 Python 3.8、舊版 numpy／scipy 上跑過。
- 正式站沒有驗證。
- 這場 57 秒的錄音拆成三軌時仍然對不起來，所以**左右兩耳之間的相位在網站流程裡還是沒有結果**。
  獨立麥克風目前只和左聲道對齊；改成和左右兩軌一起對齊可能有幫助，還沒有做。
- Opus 的雙聲道編碼對左右時間差的影響只在合成資料上測過（12 取樣點的時間差，誤差在 1.5 取樣點內），沒有用真實的 EARS 錄音量過。
- 離群窗的判斷在離群窗超過約三成時會失效（Theil–Sen 的限制）。
- 對齊後的複驗量的是「模型和自己一致」，不是和外部基準比。真實錄音沒有外部的同步基準。
- 分析頁只顯示 JSON 文字，沒有把 `track_sources` 畫成對照表。前端沒有改。
